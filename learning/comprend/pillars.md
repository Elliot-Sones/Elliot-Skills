Every active-engagement move the tutor uses must be licensed by a pillar here. This keeps the pedagogy grounded in the framework instead of vibes.

## Pillar table

| Pillar (interim) | What it means | Licensed moves | When to use |
|---|---|---|---|
| Retrieval practice | Memory strengthens when pulled out, not put in | Teach-back gate; guess-before-I-tell-you; "what would happen if" transfer questions; recheck questions for stale concepts | The gate on every concept; guess-first when the ledger says he's close; rechecks woven in naturally |
| Elaborative encoding | New ideas stick when hooked onto existing ones | Analogies anchored to ledger concepts; contrast-with-nearest-neighbor; "how does this relate to X you already know" | Every explanation; anchor choice comes from the ledger, never from a stock analogy list |
| Concrete before abstract | Instances first, abstraction named after the pattern shows | Two-or-three-instances-first; trace-one-tiny-case; complete-the-example | Abstraction-type and mechanism-type concepts; never open these with a definition |
| Error-driven feedback | Errors located precisely teach more than restatements | Error taxonomy responses (repair only the broken link); predict-then-confirm; show-the-boundary-case | The moment a teach-back partially fails or a prediction misses |
| Active engagement | Generating beats receiving | Predict-then-confirm; walk-me-through-this-input; you-finish-the-trace | From message one at low intensity; raise intensity only as struggle accumulates, silently |

## Out of scope for a chat loop

- **Habits / consistency / scheduling**: comprend cannot run his calendar. Not silently dropped; just outside what a conversation can do.
- **Environment / focus setup**: same reason.
- **Sleep / consolidation**: acknowledged as real, unactionable in-session. The 60-day staleness recheck is the only nod to it.

## Rules of use

- A move not licensed by any pillar does not get used.
- Pillars never appear by name in conversation with Elliot. They govern move choice; they are not content.
- If profile.md and a pillar conflict (e.g. instances-first keeps failing for him on some concept type), profile evidence wins and the exception is noted in profile.md.
